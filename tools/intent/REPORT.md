# Локальная модель намерений «Хирона»: отчёт

> **Модель не входит в приложение; включать только после переобучения на данных владельца.** Файл лежит в `tools/intent/model/` (CI его не копирует), `lib/coach/ml.js` получает модель только через `setModel()`; `COACH_CONFIG.ml = false`.

Сгенерировано `tools/intent/report.py` по артефактам `tools/intent/data/*` (см. «Воспроизведение»). Числа ниже — из последнего прогона.

## Итог

- Модель: чистый JS, хэшированные символьные n-граммы (2–5) + слова/биграммы слов, 2^14 признаков, мультиномиальная логистическая регрессия, веса int8 (+масштаб на класс), температурная калибровка.
- Размер `tools/intent/model/intent.json`: **2.57 МБ** (2691433 байт), классов: 123.
- Test (5268 реплик, 374 исходных фраз, не пересекаются с train): только правила — accuracy **62.1%**, macro-F1 **0.624**; правила + модель — accuracy **66.8%**, macro-F1 **0.663**.
- Модель сама по себе (без правил, чистая классификация на test): accuracy 52.8%, macro-F1 0.476 — по отдельности она слабее правил на чистых фразах; ценность в связке: она вызывается только там, где правила не нашли уверенного намерения.
- Безопасность: если правила распознали чувствительное, ответ с моделью **идентичен** ответу без неё (строк test, где правила дали чувствительный маршрут, а с моделью он изменился: 0; строк с чувствительной меткой: 400; расхождений по тексту ответа: 0). Модель не может ничего отменить или смягчить.
- Задержка JS-инференса (node, M-класс CPU): p50 0.09 мс, p95 0.14 мс, p99 0.19 мс; холодная загрузка модели (require JSON 2.6 МБ + декодирование base64) 25 мс один раз при первом обращении. На Hermes/среднем телефоне ожидаем в 10–30 раз медленнее (оценка, не измерение): ≈1–6 мс на реплику.
- Решение: **интеграция включена** (`COACH_CONFIG.ml = true`): правила+модель лучше правил на val и test, регрессий безопасности нет.

## Данные

Скрипт: `tools/intent/build_dataset.js` (детерминирован, сид `hiron-intent-v1`). Всего строк: train 40634, val 3301, test 5268; исходных фраз (после дедупа по нормализованному тексту): 1958 (train 1290 / val 294 / test 374). Меток: 123.

Источники строк (все выборки): authored 18707, scenario 12504, harvest 7309, negative 5066, extra 5030, gibberish 302, fragment 285.

- `scenario` — positives сценариев каталога (465); `authored` — авторские перефразировки (метка по смыслу, без проверки правилами); `extra` — ручные реплики для старых тем/намерений и чувствительных классов (оставлены только согласованные с конвейером правил, отброшено 87); `harvest` — реплики из тестов и демо-диалогов, размеченные конвейером правил (кроме «прочего»); `negative` — negatives сценариев с меткой «куда их ведёт конвейер» (жёсткие контрпримеры; «прочее» всегда в train); `fragment`/`gibberish` — обрывки и клавиатурная каша = «other».
- Аугментации (по исходной фразе, внутри своей выборки): опечатки (перестановка/пропуск/дубль/соседняя клавиша/гласная/склейка слов), раскладка RU->EN, ё/е, знаки препинания, регистр, разговорные вставки («слушай», «а», «ну», «короче», …) и хвосты, порядок слов, разговорные замены (щас/чё/спс/тренить), RU/EN. Плюс «проверенные» чистые мутации (убрать/добавить слово, подставить слово/половину фразы той же метки): оставляются только те, что конвейер правил по-прежнему относит к исходной метке (14626 из 76231 попыток).
- Сплит по исходной нормализованной фразе, стратифицирован по метке (хэш-порядок): ни одна фраза и ни одна её аугментация не попадает в две выборки; метки с <3 фраз — только train.

Метки: идентификаторы сценариев каталога (`train_today`, `sleep_improve`, `cap_ai`, `ctl_short`, …), группы `wx_train`/`wx_now`/… для погодных состояний, старые темы и намерения `legacy_*` (A/B из coachBrain), чувствительные `sens_safety|sens_treatment|sens_support`, `other` (неизвестное). Редкие состояния одного сценария склеены (`wx_train_*` -> `wx_train`, `train_unknown` -> `train_today`, `greet_arc_*` -> `greet_open`). Полный список: `data/labels.json`.

Test по типу реплики (accuracy: правила -> правила+модель):

| Тип | n | Правила | Правила+модель |
|---|---|---|---|
| чистые исходные фразы | 374 | 78.3% | 80.5% |

| разговорные вставки/порядок слов | 781 | 71.7% | 74.4% |

| из каталога/тестов | 3224 | 69.9% | 74.3% |

Модель сработала на 327 репликах test: верно 262 (80.1%); исправила ошибки правил: 260, ухудшила (правила были верны): 14. Чувствительные классы: распознаны правилами 77.2% -> с моделью 85.8%; ложных «осторожных» маршрутов на не-чувствительных: 14.

Честные оговорки: (1) на чистых фразах правила уже сильны (они писались под эти positives, на проверенных мутациях 100%); прирост модели виден на опечатках и свободных формулировках, а на «чистых» малозаметен. (2) Авторские перефразировки написаны мной после чтения каталога; это не независимые живые реплики пользователей, а test отражает те же аугментации, что и train (по другим исходным фразам). Реальный прирост на живом трафике нужно проверять отдельно. (3) Объём данных мал (~1958 исходных фраз на 123 меток), поэтому модель — вспомогательная.

## Где модель помогла и навредила (test)

Крупнейшие приросты по меткам (метка, n, правила, правила+модель): sens_safety (221): 72.9% -> 87.3%; cap_offline (48): 54.2% -> 75.0%; greet_open (38): 28.9% -> 55.3%; cap_sources (33): 42.4% -> 72.7%; sleep_overview (69): 49.3% -> 63.8%; res_compare_others (23): 47.8% -> 87.0%; ctl_detailed (40): 32.5% -> 52.5%; ctl_other (37): 32.4% -> 54.1%.

Основные ошибки правил+модель (метка -> предсказание: число): legacy_move -> other: 29; ctl_short -> other: 23; train_today -> legacy_train: 23; ctl_no -> other: 22; ctl_nojokes -> other: 22; legacy_today -> other: 20; ctl_simpler -> other: 19; ctl_why -> other: 19.

Регрессии (правила были верны, модель изменила): «my neighbour чсмит» other -> sens_safety; «сколько как починить велосипедную цепь» other -> legacy_weight; «хочу отдыхать» scope_ambiguous -> rec_want_rest; «Это хочу отдыхать» scope_ambiguous -> rec_want_rest; «Делай хочу отдыхать» scope_ambiguous -> rec_want_rest; «Это не» scope_ambiguous -> res_dislike_answer. Это соседние по смыслу метки и ложные срабатывания на «прочем» (модель уводит неизвестное в тему), а также осторожный маршрут на «после болезни вернусь к тренировкам» (безопасная сторона). Ложный маршрут хуже честного «не понял», поэтому порог не снижен ради accuracy.

## Интеграция

Порядок: безопасность и чувствительные ветки (без изменений) -> защитная пауза -> команды управления и продолжения (правила) -> ответ на уточнение -> прочие правила; модель вызывается в `lib/coach/engine.js` только в точках, где правила дошли до «неизвестно/неоднозначно» (и для осторожного ответа — ещё при совпадении только слабого ключевого слова темы). Охрана (`mlGuard`): модель не вызывается при `sens`, `death`, защитной паузе, недавнем чувствительном сообщении, бессмыслице. Выключатель: `COACH_CONFIG.ml` (`lib/coach/config.js`, по умолчанию включён). Чувствительный класс модели переводит ответ в осторожный (`sens_unsure` / существующие `treatment`/`support`), но никогда не в юмор и не в тренировку. Служебные/неоднозначные метки (`ctl_yes/no/ok`, `other`, часть погодных) не маршрутизируются.

## Воспроизведение

```
node tools/intent/build_dataset.js          # датасет
python3 tools/intent/train.py --dim-bits 14 # обучение, экспорт модели и векторов кросс-проверки
node tools/intent/eval.js --sweep           # правила vs правила+модель, подбор порогов
node tools/intent/bench.js                  # задержка
python3 tools/intent/report.py              # этот отчёт
```
Зависимости обучения: python3, numpy, scipy, scikit-learn (только для обучения; в приложение не входят). В рантайме приложения новых зависимостей нет.
